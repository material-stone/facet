## Required decisions

- user-visible purpose와 primary use case
- module 또는 service boundary와 ownership
- boundary 사이의 dependency direction
- public interface, schema, event, asset-loader contract
- feature 변경 중에도 유지할 invariant
- native setup, test, lint, build, architecture-check command

이름 있는 architecture style을 용어만을 위해 선택하지 않습니다. ownership과 change impact를 명확하게 하는 최소 boundary를 선택하고 의도적인 변경은 `docs/decisions/`에 기록합니다.

machine-readable 선언은 `architecture-contract.yaml`입니다. `validate_environment.py`가 이를 검사하며, project-native architecture checker가 있으면 추가로 연결합니다.
