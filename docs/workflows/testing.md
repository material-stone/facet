# 변경 범위별 검증

컨디션 게이지의 실제 누름→뗌 회귀 검사는 `dotnet run --project impls/Facet.JournalChecks/Facet.JournalChecks.csproj --no-build --no-launch-profile -- --condition-input`으로 별도 실행한다. 합성 컨디션만 가진 작은 검사 창에서 실제 포인터/마우스 버튼을 사용하며 종료 시 창을 닫고 포인터·전경 창을 복원한다. 누르는 동안 미열림, 뗀 뒤 유지, 선택 후 자동 저장과 창 유지, 중첩 시각 선택창, 별도 바깥 클릭, 바깥 놓기 취소를 확인한다. 기본/OverlayUi 검사에는 실제 입력을 포함하지 않는다.

사용자 요청(2026-10-23): 블러는 이미 확인했으므로 기능 추가 때마다 격자·빨간 배경과 탭 조작을 화면에 반복 재생하지 않는다.

기본 `./scripts/check.ps1`과 `./scripts/build.ps1`은 배포 실패 보존, Core, 구형 기록 보존·암호화 저장과 화면 밖 WPF 렌더 검사를 실행한다. 전역 단축키를 등록하거나 테스트 창을 표시하지 않는다. 앱 실행 중에도 사용자의 단축키를 건드리지 않는다.

배포 검사는 각 publish 실패·불완전한 출력·manifest 교체 실패 때 기존 선택을 보존하고, 성공하면 최신 release 하나만 유지하는지 확인한다. 잠긴 이전 배포본의 부분 삭제 방지와 잠금 해제 후 재정리, 디렉터리 링크 밖으로 삭제하지 않는 경계도 검사한다. `.test-data`의 합성 저장소·복사된 바이너리·캐시·미참조 로그는 재생성 가능한 임시 산출물이며, 과거 검증 문서에 적힌 모든 임시 경로의 영구 보관을 보장하지 않는다. 문서에서 직접 참조하는 검증 자료, 재사용할 검사 소스·도구, 원본 자산과 복구 정보는 선별해 유지한다. 배포 보존 정책은 [0057](../decisions/0057-latest-release-retention.md)을 따른다.

추가 검사는 변경한 기능에 맞춰 선택한다. build.ps1에도 동일한 switch를 전달할 수 있다.

| 변경 범위 | 추가 명령 | 화면 영향 |
| --- | --- | --- |
| 달력·탭의 동작과 배치 | `./scripts/check.ps1 -OverlayUi` | 화면 밖 렌더·직접 명령 호출. 키 입력과 배경 캡처 없음 |
| 빠른 실행·alias·후보·고스트 입력 | `./scripts/check.ps1 -OverlayUi` | 합성 PATH·파일/폴더·암호화 설정·화면 밖 입력창. 앱/탐색기 실제 실행은 하지 않고 실행 대상과 인자를 검증 |
| 대시보드 카드·F8 디버그·알림 CLI | `./scripts/check.ps1 -OverlayUi` | 합성 저장소와 실제 CLI/로컬 Pipe 왕복. 실제 사용자 알림·전역 키 입력 없음 |
| 실행기·시작 화면·버전 전환 | `./scripts/check.ps1 -Launcher` | 별도 데이터의 앱 창·오버레이를 실제 실행. 격자·빨간 배경 없음 |
| 블러·캡처·배경 전환 | `./scripts/check.ps1 -OverlayVisuals` | 격자·빨간 배경·실제 키 입력을 포함한 기존 화면 회귀 검사 |

일반 기능 추가에는 기본 검사와 관련된 검사만 실행한다. `-OverlayVisuals`는 관련 경계를 변경했거나 그 경계의 회귀를 의심할 구체적 근거가 있을 때만 선택한다. 이번 실행 정책 변경을 확인하기 위해 이 옵션을 다시 재생할 필요는 없다.

단축키만 수정한 경우 실제 키 전달은 필요한 동작만 격자·빨간 배경 없이 확인하며, 이를 이유로 전체 배경 회귀 검사를 실행하지 않는다.

JournalChecks를 직접 실행할 때는 각각 `--overlay-ui`, `--launcher`, `--overlay-visuals`를 사용한다. 화면 밖 검사는 OS의 실제 키 전달을 확인한 것으로 보고하지 않는다.

대시보드 날씨의 일반 `-OverlayUi` 검사는 주입한 Windows 좌표·위치 권한 실패·선택 지역·합성 HTTP만 사용한다. 실제 좌표나 위치 권한 요청 없이 ipapi 미호출, 수동 지역의 암호화 저장·재로드, 지역 변경 중 오래된 응답 차단과 로딩 배치 불변을 확인한다.

실제 Windows 위치 연결은 사용자가 요청한 경우에만 별도로 실행한다. 이미 허용된 위치 권한으로 좌표를 읽어 현재 날씨를 조회하며 권한 창은 띄우지 않는다. 권한이 없거나 서비스·하드웨어에서 위치를 얻지 못하면 실패를 정상적으로 보고한다:

```powershell
dotnet run --project impls/Facet.JournalChecks/Facet.JournalChecks.csproj --no-build --no-launch-profile -- --weather-live
```

최초 권한 요청은 앱 설정의 「위치 접근 허용」에서 사용자 동작으로만 실행한다. 위치 이름·좌표·IP를 테스트 로그에 출력하지 않는다. 서비스 가용성에 의존하므로 실제 연결 검사는 기본 check/build에 포함하지 않는다.

일반 창 제거 회귀는 기본 검사에서 전용 타입·트레이 경로 부재, 시작 시 계획 미생성, 구형 데이터 보존과 저장 실패 종료 취소를 검사합니다. `--hotkeys`는 격리된 세 단축키를 등록하고 HWND 메시지로 오버레이·빠른 실행을 잠깐 열어 경로와 해제를 확인합니다. 실제 키 입력이나 격자 배경은 사용하지 않습니다.
