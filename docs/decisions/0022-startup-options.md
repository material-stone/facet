# 직접 실행 표시와 로그인 자동 실행

후속 결정 [0054](0054-stable-autostart-registration.md): 이미 켜진 자동 실행은 기본 경로의 앱 시작 때 고정 실행기로 보정한다. 꺼진 상태와 검증 실행의 사용자 등록 비수정 정책은 유지한다.

2026-10-24: 설정에서 직접 실행 시 오버레이를 표시할지, Windows 로그인 시 앱을 자동 실행할지를 독립적으로 선택한다.

Settings.ShowOverlayOnLaunch는 AppData v2의 선택 설정이며 누락 시 true로 읽어 기존 일반 실행 동작을 유지한다. Settings.OverlayVisible은 현재 세션의 표시 상태로 남기고 시작 표시 설정으로 재사용하지 않는다. 직접 실행이 숨김으로 설정되어도 사용자의 전역 단축키·트레이 열기·트레이 더블클릭은 오버레이를 열 수 있다.

기존 StartupCheck는 HKCU Run의 기존 앱 값 등록 여부를 source of truth로 사용한다. 사용자가 자동 실행을 켜서 저장할 때 고정 실행기 경로와 --autostart --tray를 등록한다. --autostart는 로그인 시작을 명시적으로 구분하며 --tray는 구버전 호환과 일반 백그라운드 시작에 유지한다. 기존 --tray 등록도 계속 숨김으로 인식한다. 기능 추가·검증만으로 사용자의 실제 자동 실행 등록을 바꾸지 않는다.

Desktop과 Launcher가 공유하는 LaunchProtocol.IsBackgroundStart가 두 인자를 판별한다. 백그라운드 요청은 기존 프로세스에 open 이벤트를 보내지 않으며, 이전 버전이 실행 중이어도 로그인 시 종료 확인·업데이트 창을 띄우지 않는다. 사용자가 일반 실행 또는 관리 창 활성화로 명시적으로 버전을 바꿀 때는 두 배경 인자를 제거하고 저장된 시작 표시 설정을 따른다. 일반 재실행의 open 이벤트도 현재 메모리의 ShowOverlayOnLaunch 설정을 따른다.

검증은 구버전 기본값·명시적 false 직렬화, 시작 설정 UI의 로드·변경 감지, 합성 배포의 실제 일반/로그인/트레이 시작·기존 인스턴스 요청·표시 설정 off 재실행을 확인한다. 실제 HKCU Run 등록이나 사용자 기록은 수정하지 않는다.
