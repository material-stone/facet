# 관리 탭의 드래그 캐러셀

현재 관리 화면은 [0032](0032-single-management-screen.md)에 따라 달력 하나만 표시하며 아래 다중 항목 정책은 과거 결정이다.

현재 크기·이웃 노출·순환 경로 정책은 [0028](0028-large-carousel-viewport.md)이 아래 초기 결정을 대체한다.

2026-10-24: 기존 달력 탭의 표시 이름을 관리로 바꾸고 대시보드 → 관리 순서를 유지한다. 관리는 캐러셀 3항목을 가지며 첫 항목은 기존 달력·날짜별 할 일·마크다운 노트다. 나머지 둘은 서로 다른 배경만 표시하는 빈 항목이다.

Desktop/OverlayCarousel은 WPF Panel 내부에서 선택 항목을 항상 화면 가로·세로 중앙에 배치한다. 이전 항목은 왼쪽, 다음 항목은 오른쪽에 작게 표시하고 세 항목을 순환한다. 첫 항목의 이전은 마지막 항목이며 마지막 항목의 다음은 첫 항목이다. 선택 항목의 최대 표시 폭은 680 DIP, 나머지 항목은 그 절반이다. 간격은 가용 화면 폭의 2%를 12~32 DIP로 제한한다. 세 항목 너비와 간격의 합이 가용 폭을 넘지 않고 높이도 가용 높이에 맞는다. ClipToBounds는 끄고 바깥 여백을 두어 그림자까지 보인다. 내부 설계 좌표 960×600을 Viewbox로 축소하므로 작은 화면에서도 달력·패널 내용을 자르지 않는다. 그림자는 빈 배경 형제에만 적용한다.

드래그는 항목의 위치와 배율만 보간하고 레이아웃은 다시 계산하지 않는다. 마우스 이벤트는 마지막 좌표만 보관하며 CompositionTarget.Rendering에서 프레임당 한 번 적용한다. 이벤트 구독은 드래그 종료·캡처 상실·Unloaded에서 해제한다. 애니메이션 해제와 키보드 탐색 속성 설정은 매 마우스 이동에서 반복하지 않는다. BitmapCache는 화면 밖 CPU 실험에서 비용이 증가해 사용하지 않으며 글자는 이동 중에도 직접 렌더한다. 놓으면 새 선택 항목이 220ms 동안 중앙으로 이동하며 커지고 이전 선택 항목은 이웃 크기로 줄어든다. 순환하면서 반대편으로 돌아가는 항목은 두 전경 카드 뒤에서 이동한다. 좌우·상하 여백은 대칭이어서 선택 항목의 중앙이 창 중앙과 일치한다.

텍스트 입력란과 버튼에서 시작한 드래그는 텍스트 선택·기존 클릭을 유지한다. 다른 영역은 가로 이동 임계값을 넘어야 캡처하며 이동한 드래그의 mouse-up은 소비한다. 이웃 항목의 클릭은 내부 컨트롤에 전달하지 않는다. 드래그 미리보기는 저장·마크다운 재생성을 실행하지 않는다. 항목 변경을 확정하는 mouse-up 또는 Select에서 OverlayTabs가 기존 DayEditor의 남은 입력 저장을 확인한다. 실패하면 선택과 초안을 유지하며 포커스 이동도 알리지 않는다. 비활성 항목은 키보드 탐색에서 제외하고 달력 단축키는 첫 항목에서만 동작한다. 저장 스키마·Core·배경 캡처는 변경하지 않는다.

검증은 화면 밖 WPF에서 크기별 모든 항목의 경계·간격과 드래그 도중 경계, 이벤트 병합·레이아웃 유효성, 방향·임계값·양 끝·입력란 제외·클릭 억제, 저장 시점·실패 시 이동 차단과 기존 날짜/할 일/노트 기능으로 수행한다. CPU 성능 측정은 JournalChecks의 --carousel-profile로 재현하며 실제 화면의 GPU 프레임율을 뜻하지 않는다.
