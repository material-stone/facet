# 다운로드 음원 재생과 제목 표시

2026-10-27: 사용자가 작업표시줄 위 현재 제목·여백 제거, YouTube URL 다운로드 재생과 반복적인 취소 문제 해결을 요청했다. 기본 transport를 headless browser에서 MusicDownloadCache + WPF MediaPlayer로 교체한다. 처음 재생 시 AAC/M4A 음원을 받고, 성공한 파일만 Store.Root/MusicCache에 원자적으로 확정한다. 이후 같은 video ID는 캐시를 재사용하며 로컬 재생에는 브라우저·네트워크·광고가 개입하지 않는다. 기존 URL·제목·반복·목록 저장 형식은 유지한다.

Desktop/DashboardMusic만 다운로드 CLI·도구 loader·캐시·로컬 MediaPlayer를 소유한다. 공식 yt-dlp2026.10.26 exe와 라이선스를 feature 폴더에 동봉하고 실행 전 고정 SHA256을 검증한다. 설치된 Node22 이상을 JS runtime으로 사용하며 인증 토큰·쿠키·개인 브라우저 프로필·앱 기록은 전달하지 않는다. 입력은 검증한 video ID 한 개뿐이며 DRM·로그인·지역 제한을 우회하지 않는다. 자동 업데이트·임의 플러그인·원격 코드 다운로드는 사용하지 않는다. 호환 M4A가 없거나 다운로드가 실패하면 명확한 오류를 표시하며 광고가 있는 재생으로 몰래 fallback하지 않는다.

로컬 캐시는 video ID로 경로를 고정하고 임시 파일·완성 파일을 구분한다. title·완료 metadata와 파일이 함께 정상일 때만 재사용한다. 이름과 외부 경로를 실행 인자/저장 경로로 사용하지 않으며 앱의 기록·이전 캐시를 다운로드 실패 때문에 삭제하지 않는다. 성공한 소유 음원에만 MediaPlayer.Open을 호출한다. 앱 종료는 플레이어를 닫고 진행 중인 다운로드 자식 프로세스만 취소한다.

MusicPlaybackService는 늦게 완료한 재생 요청이 새 선택을 덮어쓰지 않게 세대를 대조하며, 진행 중이라는 이유로 후속 선택을 무시하지 않는다. 제목 저장 실패는 재생을 멈추지 않는다. 숨김·탭 이동·패널 해제는 계속 재생하고 반복·다음 곡은 공통 수명을 유지한다.

MusicPlaybackIndicator는 ‘♫ 재생 중 · 현재 제목’을 한 줄로 표시한다. 2026-10-27 후속 요청에서 여백0의 의미를 실행 알림 토스트와 같은 모양으로 정정했다. ToastWindow startup과 같은 Panel 배경·Mint1 DIP 테두리·8 DIP 모서리·좌우12/상하7 DIP padding·13 DIP 글씨와 작업표시줄 위16 DIP 간격을 사용한다. 추가 요청에 따라 전체 최대 폭은280 DIP로 줄이고20 DIP 콘텐츠 행 안에서 글자의 실제 ink bounds를 수직 중앙에 맞춘다. 고정 상태 표시 오른쪽에서 넘치는 제목만 clip해28 DIP/초로 왕복 이동하며 양 끝에서1.2초 쉰다. 짧은 제목은 움직이지 않고 제목 변경·숨김은 이전 animation을 정리한다. 같은 제목의 주기 갱신은 스크롤을 재시작하지 않는다. 제목 갱신은 창을 재생성하거나 포커스를 빼앗지 않으며 음악 표시는 재생 중 계속 유지되고 클릭·포커스를 가로채지 않는다.

음악 토스트의 배경·테두리·상태·제목을 모두 반투명하게 해 달라는 추가 요청에 따라 Window.Opacity를0.7로 적용한다. 전체 불투명도70%·투명도30%로 합성하며 공유 brush나 실행 알림 토스트는 변경하지 않는다.

검사는 합성 파일·fake download로 완료/실패·캐시 재사용·경로·새 선택·로컬 재생 수명과 제목 표시를 확인한다. 실제 사이트 연결 검사는 파일을 저장하지 않는 metadata probe와 Creative Commons Blender 영상의 다운로드·음소거 native 재생으로 분리한다. 다운로드할 권한이 있는 콘텐츠를 사용한다. 캐시는 일반 M4A 파일이며 목록·반복 설정은 기존 암호화 Store를 유지한다.
