# 스킨 토큰 구조

2026-11-04: 교체 가능한 스킨의 첫 단계로 앱 UI 색의 소유 위치와 적용 시점을 정한다. 기본 스킨의 표시 결과는 바꾸지 않는다.

2026-11-04 추가: 내장 스킨 선택을 추가한다. `Design/Skins`가 목록과 로드를 소유하고, 기본 스킨은 `Tokens.xaml` 자체이며 다른 스킨은 `Design/Skins/<Id>.xaml`을 뒤에 병합해 같은 키를 덮어쓴다. 선택 필드 `Settings.Skin`(누락·알 수 없는 값은 `default`)을 Controller가 저장소를 읽은 직후, 첫 창을 만들기 전에 적용한다. 설정의 스킨 선택은 자동 저장되고 다음 시작부터 적용된다. 내장 스킨은 모든 색 토큰을 정의해야 한다. 오버레이 배경색은 사용자 설정이라 스킨이 바꾸지 않으므로, 밝은 글자를 전제로 하지 않는 스킨은 이 경계를 먼저 다시 정해야 한다.

- `Design/Tokens.xaml`이 스킨이 바꿀 수 있는 앱 UI 색의 단일 소유자다. 화면은 토큰 키로만 앱 UI 색을 참조한다. 흩어져 있던 모달 배경과 음악 오류 글자색을 `ModalBackdrop`, `DangerSoft` 토큰으로 옮겼다.
- 스킨은 첫 창을 만들기 전, 앱 시작 시 토큰 사전을 교체해 적용한다. 그래서 기존 `StaticResource`와 C# `FindResource`를 그대로 쓴다. 실행 중 전환은 모든 참조와 C#에 저장된 브러시를 바꿔야 하므로 필요해질 때 별도로 결정한다.
- 토큰이 아닌 색: 사용자 데이터(일정·프리셋 색, `OverlayBackgroundColor`와 그 팔레트·기본값), 컨디션 종류별 색(`ConditionIcons`), 색 선택기의 기능 색(그라데이션·선택 표시), 벡터 그림자의 검정. 일정·수면 모달 배경은 계속 사용자 오버레이 색에서 만든다.
- 외부 스킨을 받게 되면 임의 객체를 만들 수 있는 XAML을 불러오지 않고, 검증한 데이터(JSON과 에셋)만 받아 로드·검증 module 뒤에 둔다.
