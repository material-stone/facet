# 달력·일정 위젯과 전용 저장소

2026-11-05: 일정 탭의 고정 화면이던 달력과 하루 일정 관리를 내장 위젯 `builtin.calendar` 하나로 옮기고, 날짜별 일정·할 일·기록을 전용 파일 `<data>/calendar.dat`에 저장한다.

## 결정

- **위젯**: 달력과 일정 관리 화면은 한 타일 안에서 기존 좌우 페이드로 전환한다. 한 탭에 하나만 놓을 수 있고 기본 크기 14×8, 최소 8×5다. 키보드·Esc 동작은 위젯이 놓인 탭에서 그대로 동작한다. 일정 수정 모달은 타일에 잘리지 않도록 오버레이 전체에 둔다.
- **레이아웃 이전**: `GridVersion` 3부터 위젯이 기본 배치다. 저장된 이전 레이아웃에는 한 번만 일정 탭 빈 자리에 추가하며, 이후 사용자가 제거하면 다시 넣지 않는다.
- **저장소**: `calendar.dat`는 `records.dat`와 같이 DPAPI 암호화·원자 교체·`.bak1~5`를 쓴다. `WidgetStores`(값 64K 제한)는 하루 노트 20,000자·일정 다수를 담기에 맞지 않는다. 메모리에서는 `AppData.CalendarDays`를 유지해 도구·알림·롤백 코드를 바꾸지 않고 `Store`만 파일을 나눈다.
- **이전**: `records.dat`에 날짜 기록이 있으면 먼저 `<data>/backups/records-before-calendar-store-*.dat`로 복사·해독 검증하고, 저장소에 복사해 다시 읽어 일치를 확인한 다음에만 `records.dat`에서 비운다. 실패하면 원본을 건드리지 않고 시작 오류로 알린다.
- **일정 프리셋**: 일정의 일부이므로 `SchedulePresets`도 `calendar.dat`에 두고 같은 절차로 옮긴다. 저장소에 목록이 있으면 저장소가 이긴다.
- **병합**: 이미 저장소가 있는데 `records.dat`에 날짜 기록이 또 있으면(구버전 실행 등) 다시 백업하고 저장소에 없는 날짜만 채운다. 같은 날짜는 저장소가 이기며 밀린 내용은 백업에 남는다.
- **저장 순서**: `records.dat`를 먼저 쓰고 날짜 기록이 바뀐 경우에만 `calendar.dat`를 쓴다. 관계없는 저장이 달력 백업을 밀어내지 않는다.

## 한계

두 파일은 한 트랜잭션이 아니다. `records.dat` 저장 후 `calendar.dat` 저장이 실패하면 호출자가 실패로 처리해 메모리를 되돌리며, 달력 기록과 다른 기록은 서로 참조하지 않아 불일치가 생기지 않는다. 이전 후 구버전 앱을 실행하면 달력이 비어 보인다. 위젯을 제거해도 데이터는 지우지 않는다.
