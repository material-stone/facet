# 달력에서 전환하는 하루 파이 일정

날짜 경계의 현재 저장/표시 정책은 [0035](0035-cross-date-schedules.md)가 이전 날짜 순환 표시를 대체한다.

2026-10-24: 관리 첫 항목은 중앙 달력으로 시작한다. 날짜 클릭/Enter는 달력을 왼쪽으로 페이드 아웃하고 하루 화면을 오른쪽에서 페이드 인한다. 하루 화면에는 왼쪽 색상/레이블 범례와 24시간 파이, 그 위 날짜/요일, 오른쪽 할 일과 기록을 배치한다. Esc는 모달 취소 → 하루 저장 후 달력으로 역전환 → 오버레이 숨김 순서다. 하루 화면의 캐러셀 드래그는 잠가 파이 드래그와 충돌하지 않는다. 월/오늘/방향키 탐색은 달력에서만 동작한다.

Core/CalendarNotes의 기존 날짜 초안에 선택 Schedules 목록을 추가한다. 누락 시 빈 목록이며 기존 할 일과 Markdown 원문을 보존한다. 일정은 이름, 시작 분, 길이, #RRGGBB 색상과 레이블 한 쌍, 내용을 저장한다. 30분 단위로 최대 24시간까지 허용하며 자정 통과도 같은 시작 날짜에 보관한다. UI/파일 의존성은 Core에 추가하지 않는다.

Desktop/OverlayScheduleDial은 0시가 위, 12시가 아래인 시계 방향 48칸을 그린다. hover는 저장 일정과 이름의 채움을 같은 비율로 밝히고 드래그는 통과한 호를 따라 채운다. 내부 격자와30분 hover 칸은 그리지 않는다. 같은 칸에서도 8 DIP 이상 움직이면 선택한다. 양 방향/자정 통과 드래그를 지원한다. 큰 일정부터 그리며 겹치는 짧은 일정의 반경을 줄여 그 위에 그린다. 연결선은 대각선과 수평선으로 왼쪽 레이블까지 이어진다. 범례는 색상/레이블 쌍으로 묶는다.

2026-10-25 범례 높이: 범례는 다이얼 영역의 위아래20 DIP 여백 사이를 최대 높이로 사용한다. 항목이 적으면 아래 정렬을 유지하고 많으면 이 높이를 다 사용한 뒤에만 스크롤한다. OverlayTabs가 실제 범례 ScrollViewer 경계를 다이얼 좌표로 전달하며 일정 이름 상자는 이 영역과 여유 공간을 피해서 배치한다. 범례 크기나 다이얼 크기가 바뀔 때만 배치 캐시를 갱신한다.

2026-10-25 명칭·편집 양식: 탭 표시 이름과 접근성 이름은 ‘일정’으로 통일한다. 새 항목 모달 제목은 ‘새 일정’, 기존 항목은 ‘일정 수정’이다. 이름·날짜/시간·색상/레이블·내용을 각각 묶고 그룹 사이 간격은24 DIP, 레이블과 입력 간격은10 DIP로 통일한다. 색상 프리셋은 색상/레이블 입력 아래8 DIP 간격으로 같은 그룹 안에 둔다. 입력 컨트롤의 공용 바깥 여백은 이 양식에서 제거하고 그룹이 간격을 소유한다.

2026-10-25 색상 선택: 색상 코드 필드를 클릭하거나 포커스 상태에서 Enter/Space를 누르면 OverlayScheduleColorPicker를 연다. 색조 막대는 선택 창이 직접 로드하는 전용 스타일로 무지개 그라데이션과 속이 빈 위치 표시자만 그려 기본 슬라이더의 수평 선이 색을 가리지 않게 한다. 채도/밝기 평면·색조 막대·#RRGGBB 입력으로 선택하며 유효한 값만 일정 초안에 즉시 반영한다. 잘못된 코드 입력은 마지막 유효 색상을 덮어쓰지 않는다. 색상 코드 필드 왼쪽에는18 DIP 미리보기를 표시하고 처음 열기·선택 창·프리셋의 유효 코드 변경에 함께 갱신한다. 미리보기 클릭도 색상 코드 필드와 같은 선택 창을 열며 별도 Tab 정지점은 추가하지 않는다. 기존8개 프리셋은 그대로 유지한다. 날짜/시간 선택과 같은 독립 Canvas host·빈 배경 그림자를 재사용해 부모 일정 모달의 크기와 텍스트 선명도를 유지하며 두 선택 창은 동시에 열지 않는다. Esc/바깥 클릭은 최상위 색상 선택 창만 닫고 색상과 일정 초안은 유지한다. 일정 모달을 닫을 때 기존 검증·자동 저장 경로로 저장한다.

OverlayScheduleEditor는 별도 native 창 대신 같은 화면의 모달이며 이름/시작·종료/색상·레이블/내용, 수정·삭제를 지원한다. 기존 날짜들의 색상/레이블 쌍을 재사용한다. OverlayDayEditor가 같은 초안의 모든 내용을 저장하므로 자동 저장이 일정 변경을 덮어쓰지 않는다. 저장 실패 시 모달과 초안을 유지하고 화면 이탈을 막는다. 배경 캡처 경계는 변경하지 않는다.

검증은 Core의 구버전·깊은 복사·입력 검증·자정 통과와 WPF 화면 밖 전환, 선택 임계값, 드래그 방향, 겹침, 암호화 저장/실패 보존, 크기별 렌더로 수행한다.

2026-10-24 화면 정리: 뒤로 가기는 왼쪽 꺾쇠 아이콘으로 표시하고 같은 행에 연월일/요일을 세로 중앙 정렬한다. 오른쪽 날짜 제목과 상시 드래그 안내·하루 소개 문구, 일정 추가 버튼과 수정 선택 목록은 제거한다. 일정 생성은 파이 드래그, 수정 선택은 부채꼴 클릭으로 같은 모달을 열며 제출 버튼의 표시 이름은 확인이다. 포커스 순서에서는 제거된 컨트롤을 제외하고 날짜별 초안/저장 경계는 유지한다.

2026-10-24 여백·다이어그램 표시: 날짜 패널의 전체 스크롤 StackPanel을 할 일 목록 스크롤과 남은 높이를 채우는 기록 Grid로 나눈다. 대칭 padding과 기록 보기/편집 영역의 동일 경계를 유지하고 저장 상태는 기록 제목 행으로 옮긴다. 생성된 일정은 최대 반경의 90%부터 겹침 규칙을 적용하며 불투명하게 그린다. 원 안을 hover하는 동안의 격자는 일정보다 먼저 그려 가리고 바깥 10% 링은 생성 드래그에 남긴다. hit-test도 같은 반경을 사용한다.

2026-10-24 레이블 배치: 달력의 기존 host 크기는 유지하고 하루 화면은 독립 Viewbox에서 더 넓게 배치해 날짜 패널을 오른쪽으로 옮긴다. 다이어그램의 양쪽·모서리 공간에서 시계 눈금과 범례, 다른 레이블을 피하는 가까운 위치를 고른다. 연결점은 부채꼴의 중앙각에 고정하지 않고 내부 각도 중 가까운 쪽을 택하며 굵은 선은 원 바깥으로 우회한다. 이름은 일정 색상 테두리의 불투명 둥근 상자에 표시하고 연결선보다 나중에 그려 선이 이름을 가리지 않게 한다. 배치와 연결 geometry는 일정·크기·DPI 변경 때만 계산해 hover 렌더에서 재사용한다. 공간이 부족한 초과 레이블은 개수로 알리고 부채꼴 클릭 편집은 계속 지원한다.

2026-10-24 일정 클릭·hover: 이름 badge와 실제 부채꼴을 하나의 일정 hit-test 경로로 통합한다. 이름은 원 바깥에서도 클릭할 수 있고 같은 일정에서 mouse-down/up이 완료되면 기존 수정 모달을 연다. 일정에서 시작한 드래그는 새 범위를 만들지 않으며 빈 원/바깥 링의 생성 드래그는 유지한다. 저장 일정 위에서는 해당 부채꼴 전체의 불투명 채움/테두리와 이름 테두리를 강조하고 30분 hover 칸은 그리지 않는다. 겹침은 가장 위의 짧은 일정 우선이며 이름에서도 같은 일정과 손 커서를 연결한다.

2026-10-24 hover 채움 정책: 이 문단이 앞선 격자/hover 테두리 정책을 대체한다. 이름 hover와 sector hover는 동일한 일정의 전체 채움과 이름 배경에 공통22% white blend를 적용한다. 기존 테두리 색상·두께는 바꾸지 않는다. 방사형 격자와 빈 칸 hover geometry는 제거하며 바깥 시간 눈금과 실제 드래그 선택 미리보기는 유지한다. 클릭 모달과 바깥 생성 링 동작은 유지한다.
