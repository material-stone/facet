# ADR 0110: 스킨 위젯 레이어 — 플러그인은 데이터와 동작, 스킨은 외형과 상호작용

2026-11-17: 스킨이 배경뿐 아니라 위젯과 탭의 외형, 상호작용까지 정의한다. [0108](0108-cat-widget-form.md)의 "고양이 형태는 플러그인 C# 코드"를 대체하고, [0091](0091-world-page-in-skin.md)의 "사용자 기록을 페이지에 넘기지 않는다"를 바꾼다.

## 결정

- **레이어:** 아래부터 스킨 배경(2D·3D) → 위젯 레이어 → 앱 레이어. 위젯 레이어에는 탭 막대를 포함한 모든 위젯이 있다. 스킨이 외형을 정의한 위젯은 스킨 월드 페이지가, 나머지는 기본 WPF 모양이 그린다. 앱 레이어에는 편집 틀, 모달(설정 포함), 아이콘 메뉴만 있다.
- **구현 한계:** 페이지가 그리는 위젯은 오버레이 창 아래의 월드 창에 있으므로, 페이지 위젯과 WPF 위젯이 겹치면 WPF 위젯이 늘 위에 보인다. 위젯끼리는 겹치지 않게 배치하므로 실제로는 드러나지 않는다.
- **플러그인 = 데이터와 동작:** 위젯은 `IWidgetState`로 상태를 이름과 버전이 붙은 형식(예: `facet.clock/time@1`)의 JSON으로 내보내고 바뀔 때 다시 알린다. 동작은 이름과 JSON 인자로 공개하고(예: `record {kind}`), 검사와 저장은 플러그인이 한다. 기본 WPF 모양은 그대로 플러그인에 있다.
- **스킨 = 외형과 상호작용:** `skin.json`의 `theme.widgets`에 페이지가 그리는 형식을 적는다. 앱은 그 형식을 내보내는 위젯에 대해 WPF 모양 대신 투명한 타일을 두고, 페이지에 `{ widgets: [{ id, type, x, y, width, height, baseWidth, baseHeight, state }] }`를 보낸다. 페이지는 기본 크기로 그린 뒤 타일 크기로 늘인다([0109](0109-widget-pixel-size-and-icon-menu.md)).
- **입력:** 스킨 위젯 타일 위의 포인터(이동, 누르기, 떼기, 휠)는 위젯 기준 좌표로 페이지에 넘긴다. 페이지는 `{ type: 'action', id, name, args }`로 동작을 요청한다. 편집 모드에서는 입력을 넘기지 않고 앱이 배치를 맡는다.
- **탭:** 탭 막대는 앱이 제공하는 위젯 `facet.app/tabs@1`(상태: 탭 목록과 선택, 동작: `select {id}`)이다. 사용자가 옮길 수 있고([0109](0109-widget-pixel-size-and-icon-menu.md)), 스킨이 정의하면 페이지가 그리고, 아니면 기본 모양이다.
- **개인정보:** 일정 제목 같은 사용자 기록이 페이지로 넘어간다. 네트워크 차단(CSP, 죽은 프록시, 이동 취소)은 그대로이고, 위젯 레이어를 쓰는 스킨은 페이지 스킨처럼 관리자 검토를 거친다.

- **옵션과 소리(추가):** 앱은 스킨의 `theme.options` 값을 `{ options: { id: bool } }`로 페이지가 준비될 때와 설정이 바뀔 때 보낸다(같은 값은 다시 보내지 않음). 월드 창은 입력을 받지 않아 사용자 제스처가 생기지 않으므로 WebView2 환경에 `--autoplay-policy=no-user-gesture-required`를 더해 페이지의 WebAudio가 시작되게 한다. 네트워크 차단 인자는 그대로 함께 쓴다. 페이지는 `{ visible:false }`에서 소리 루프를 멈추고 AudioContext를 일시정지한다. 고양이 방은 이것으로 코드 합성 효과음과 `sound`(효과음) 옵션을 둔다.

## 결과

- 플러그인을 바꾸지 않고 스킨만으로 위젯 외형이 바뀐다. 상태를 내보내지 않는 예전 플러그인은 기본 모양으로 보인다.
- 형식 이름과 버전이 플러그인과 스킨 사이의 계약이 된다. 형식을 바꾸면 버전을 올린다.
