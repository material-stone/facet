# 0088 — 패키지 설치와 GitHub 레지스트리

스킨과 플러그인을 앱 빌드와 독립된 모듈로 다룹니다. 폴더에 넣으면 인식하고, 인터넷이 되면 목록에서 받거나 올릴 수 있습니다. [0074](0074-skin-token-structure.md)의 "외부 스킨은 검증된 데이터만"과 [0077](0077-theme-visual-slots.md)의 내부 형식 제한을 이 결정으로 엽니다.

## 결정

- **외부 스킨:** `<data>/skins/<폴더>/skin.json`과 PNG만 씁니다. 색은 정해진 토큰의 hex 값, 시각 효과는 기존 `ThemeManifest` 슬롯만 받습니다. XAML은 읽지 않습니다. 망가진 폴더는 건너뛰고, 내장 스킨 ID는 대체할 수 없습니다.
- **패키지:** 루트에 `plugin.json`이나 `skin.json` 하나를 둔 zip입니다(GitHub 첨부가 허용하는 형식). `Packages`가 경로 이탈, 장치 이름, 대체 스트림, 크기, 파일 수를 검사하고 임시 폴더에 푼 뒤 교체합니다. 실패하면 기존 파일을 유지합니다. 스킨에는 실행 파일을 넣을 수 없습니다.
- **서버:** 별도 서버 없이 공개 GitHub 저장소를 씁니다. `index.json`이 목록이고 파일은 Releases에 둡니다. 운영 비용이 없고, 계정·인증·저장을 GitHub에 맡깁니다.
- **받기:** 설정의 패널을 처음 볼 때 목록을 한 번 읽고, 이후에는 사용자가 누를 때만 네트워크를 씁니다. 앱은 해당 저장소의 릴리스 URL만 받아들이고 SHA-256, 종류, ID, 버전이 목록과 모두 같을 때만 설치합니다. 자동 업데이트는 없습니다.
- **올리기:** 앱은 토큰을 다루지 않습니다. zip을 만들고 브라우저의 제출 양식을 엽니다. 스킨은 자동 검증 후 공개하고, 플러그인은 pull request로 대기하며 관리자의 병합이 승인입니다. 같은 ID는 처음 올린 작성자만 갱신합니다.
- **적용:** 목록에서 **적용**을 누르면 내려받고 바로 적용합니다. 스킨은 선택되고, 플러그인은 켜집니다. 검토된 목록에서 고른 이 클릭을 [0073](0073-widget-grid-and-plugins.md)의 명시적 활성화로 봅니다. 폴더에 넣거나 zip으로 설치한 플러그인은 지금처럼 직접 켭니다.

## 한계

- 플러그인은 여전히 샌드박스가 아닙니다. 관리자 승인은 코드 안전을 보증하지 않으며, 이미 켠 플러그인을 업데이트하면 사용자가 다시 켜지 않아도 다음 시작 때 새 코드가 실행됩니다([0079](0079-plugin-auto-reload-at-launch.md)). 업데이트는 사용자가 직접 눌러야만 일어납니다.
- SHA-256은 목록과 파일의 일치만 보장합니다. 목록의 신뢰는 레지스트리 저장소 쓰기 권한에 달려 있고, 패키지 서명은 없습니다.
- 제출 처리는 GitHub Actions에 의존합니다. 첨부 URL 형식이 바뀌면 `registry/tools/submission.py`를 고쳐야 합니다.
- 앱 안에서의 패키지 제거는 없으며 폴더를 지웁니다. (플러그인 삭제와 레지스트리 위치는 [0097](0097-plugin-uninstall-and-in-repo-registry.md)이 대체)
- 앱과 레지스트리의 검증 규칙은 언어가 달라 두 곳에 있습니다. 앱이 설치 때 다시 검사하므로 앱의 규칙이 최종 기준입니다.
