# 최신 배포본만 유지

2026-10-25: 사용자는 새 빌드 이후 과거 배포본을 자동 삭제하고 최신 버전만 유지하도록 요청했다. 배포 실패 시 기존 앱을 보존하는 원자 교체 정책은 유지한다.

`scripts/build.ps1`은 배포 경로별 mutex로 동시 빌드를 막는다. 검사·앱·CLI·실행기 publish가 성공하고 `latest.json`을 원자 교체한 뒤 `releases/`의 이전 디렉터리와 오래된 staging, `latest.previous.json`을 제거한다. publish나 commit 실패 시 새로 만든 release·staging만 제거하고 기존 manifest와 release는 보존한다. 이전 manifest 백업으로 과거 배포본을 계속 보관하지 않는다.

삭제 대상은 배포 루트 바로 아래의 staging 또는 releases 바로 아래의 디렉터리로 제한한다. 경로 탈출과 reparse point를 거절하고 삭제 전에 모든 파일을 독점 열기로 검사한다. 실행 중인 이전 앱은 강제 종료하지 않고 파일 잠금이 있으면 해당 디렉터리 전체를 남겨 다음 성공 빌드에서 다시 시도한다. 잠금은 새 빌드의 실패로 취급하지 않으며 경고로 알린다.

`.test-data`는 생성 가능한 합성 저장소·복사된 바이너리·빌드 캐시·미참조 로그를 정리한다. 문서가 가리키는 검증 자료, 재사용할 검사 소스·도구, 원본 자산과 복구 정보는 유지한다. 실제 사용자 데이터 경로는 정리하지 않는다. 임시 검증 경로는 영구 자료 보관소가 아니며 장기 보존이 필요하면 docs의 해당 concern으로 옮긴다.

합성 배포 검사로 각 publish 실패, commit 실패, 성공 후 최신 release 하나만 유지, 잠긴 이전 버전 보존과 잠금 해제 후 재시도, 경로·링크 경계를 검증한다. 실제 Release 빌드로 현재 배포 정리도 확인한다. 이 결정은 0014·0056의 과거 배포본 보관 정책을 대체한다.
