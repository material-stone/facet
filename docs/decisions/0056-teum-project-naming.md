# Teum 프로젝트와 배포 이름 통일

2026-10-25: 사용자 요청에 따라 문서·소스 폴더·프로젝트 파일·namespace·assembly·실행 파일·새 배포 경로를 Teum으로 통일한다. 프로젝트 참조, WPF pack URI, 공유 source link, 검사 명령과 manifest의 필수 파일 검증도 함께 갱신한다. 계층과 의존 방향, 저장 schema는 바꾸지 않는다.

새 고정 실행기는 `artifacts/Teum/Teum.Launcher.exe`, 앱은 `releases/<build>/Teum.exe`, CLI는 `Teum.Cli.exe`다. `Start-Teum.cmd`는 새 실행기를 연다. 빌드 성공 후에만 manifest를 원자 교체하는 정책을 유지한다.

기록을 복사하거나 새 저장소를 만들지 않는다. LaunchProtocol의 기존 기본 데이터 경로·AppUserModelID·인스턴스 이벤트와 환경 변수, ReminderProtocol의 pipe 이름, SettingsEditing의 기존 Run 값 이름은 호환 식별자로 유지한다. 이 문자열은 파일명이나 제품명이 아닌 이전 실행본과 공유하는 프로토콜이다. 기본 경로의 새 앱을 직접 실행하면 기존 활성 Run 항목만 새 고정 실행기로 보정한다.

`artifacts/`에는 Teum 배포본만 둔다. 과거 배포본 11개는 처음에 별도 보관했으나, 사용하지 않아 보관할 필요가 없다는 사용자 요청에 따라 보관 폴더와 이동 목록을 함께 삭제했다(약 5.84 GiB). 현재 Teum 배포본과 실제 사용자 기록은 유지한다. 과거 테스트 결과와 이름 변경 전 소스 복구용 백업은 이번 배포본 정리 대상에 포함하지 않는다. 이전 실행기를 가리키는 고정 바로가기는 새 실행기로 한 번 다시 고정해야 한다. 새 실행기는 새 배포 manifest만 따른다. 기존 앱을 강제 종료하거나 실제 기록·Windows 바로가기를 일괄 이동하지 않는다.

이 결정은 표시 이름만 변경하고 프로젝트·배포 이름을 유지하던 정책과 0014의 고정 실행기 경로를 갱신한다. 새 배포 경로로 전환한 이후에는 동일한 Teum 실행기 경로와 기존 AppUserModelID를 계속 사용한다.

기본 검사, 화면 밖 UI·CLI 검사와 합성 Launcher 검사로 리소스 로드·암호화 기록·인자 전달·manifest 검증·버전 전환을 확인한다. 기존 데이터·이벤트·Run 식별자가 유지되는지도 검사한다. Graphify는 프로젝트 유지보수 명령으로 전체 갱신한다.
