# 오버레이 캡처 허용과 캡처 도구 우선 표시

2026-10-24: 사용자는 켜진 오버레이 자체를 Discord 화면 공유와 Windows 캡처 도구에 포함하고, 캡처 도구의 선택 UI가 오버레이 위에 표시되기를 원한다.

OverlayWindow의 WDA_EXCLUDEFROMCAPTURE 적용을 제거한다. 캡처 제외는 다른 앱에도 적용되므로 자체 배경 캡처에만 한정할 수 없다. 자기 화면이 반복해서 블러에 들어가지 않도록 기존 비동기 단일 프레임 경로를 기본 동작으로 사용한다. 창을 숨긴 상태에서 배경 한 장을 읽고 표시 중에는 고정하며, 다음 열기에서 새 배경을 읽는다. 캡처 실패·취소·이전 worker 종료 대기 정책은 유지한다. 실시간 뒤 화면 갱신보다 오버레이 캡처 가능성을 우선하며 0011·0021의 실시간 갱신/캡처 제외 정책을 대체한다.

Native는 보이는 최상위 창의 프로세스 이름을 확인해 SnippingTool, ScreenClippingHost, ScreenSketch, SnipAndSketch를 인식한다. 최소화되거나 DWM이 숨긴 창은 제외하고 프로세스 종료·접근 실패는 무시한다. OverlayWindow가 표시된 동안 150ms마다 확인하며 비활성화 시에도 즉시 확인한다. 캡처 도구의 편집 창 또는 선택 UI가 보이면 Topmost를 해제하고, 모두 닫거나 최소화하면 복구한다. 이때 Activate나 SetForegroundWindow는 호출하지 않으며 일반 앱으로 전환할 때는 기존 Topmost 정책을 유지한다. CoverScreen도 임시 해제 상태와 창 순서를 보존한다. 숨김·종료 후에는 감시하지 않는다.

검증은 합성 창으로 native 표시/최소화 감지와 Topmost 해제·복구·포커스 보존을 확인한다. 단일 프레임·실패·늦은 완료 취소를 기존 worker 검사로 확인하고 합성 배경 위 실제 화면 캡처에 오버레이가 포함되는지 검사한다. 사용자 화면이나 기록은 검증 파일에 저장하지 않는다.
