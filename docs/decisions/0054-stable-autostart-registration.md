# 로그인 자동 실행 경로 보정

2026-10-25: 로그인 때 구형 버전 실행 파일에 `--tray`를 붙인 명령가 실행되어 최신 단축키를 해석하지 못하는 오류가 발생했다. 새 배포는 기존 Run 등록을 바꾸지 않았고 SettingsEditing.SetStartup은 등록 여부가 같으면 경로를 확인하지 않고 반환했다.

Desktop/SettingsEditing이 기존 HKCU Run의 기존 앱 항목과 고정 실행기 경로 보정을 소유한다. 기본 데이터 경로의 App.OnStartup에서 Controller 생성과 단일 인스턴스 확인보다 먼저 이미 켜진 등록만 `Facet.Launcher.exe --autostart --tray`로 보정한다. 자동 실행이 꺼져 있으면 등록을 만들지 않으며 다른 시작 항목은 수정하지 않는다. 동일한 명령은 다시 쓰지 않는다. 권한·I/O 실패는 앱 시작을 막지 않고 가능한 경우 기존 트레이 경고로 안내한다.

명시적인 자동 실행 켜기도 현재 명령 전체를 비교해 구형 경로를 교체한다. 고정 실행기를 찾지 못하면 버전별 실행 파일로 대체하지 않고 켜기를 실패 처리한다. 시작 시 자동 보정은 실행기가 없으면 기존 등록을 유지한다. `--data-dir`와 `--storage-check`를 사용하는 검증은 사용자 Run 등록을 변경하지 않는다.

이 결정은 [0014](0014-stable-launcher.md)의 기존 등록 비수정 정책과 [0022](0022-startup-options.md)의 사용자 토글 전용 갱신 정책을 대체한다. 자동 실행 여부와 직접 실행 표시 설정의 독립성, 숨김 로그인 시작, 저장·데이터 형식은 유지한다.

기본 JournalChecks에서 임시 HKCU 테스트 키로 구형 경로·인자 보정, 반복 실행, 꺼진 상태 유지, 실행기 누락, 명시적 켜기·끄기와 무관한 값 보존을 확인한다. Launcher 검증은 별도 데이터 디렉터리의 기존 시작·버전 전환 검사를 재사용한다. 테스트는 실제 Run 키를 수정하지 않는다.
