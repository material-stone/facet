# 위젯 격자·사용자 탭·플러그인

2026-11-04: 고정 `StackPanel` 대시보드와 XAML 고정 탭을 12×8 타일 격자와 사용자 탭 구성으로 바꾸고, 외부 .NET 플러그인이 위젯을 추가할 수 있게 한다. [0062](0062-independent-compact-music-float.md)의 "음악은 대시보드 바깥 Canvas" 배치를 대체한다. 음악은 기본 배치의 오른쪽 타일이며 재생 수명은 그대로 Controller 소유다.

## 결정

- **저장**: AppData 선택 필드 `Workspace`(탭 순서·숨김·제목·위젯 배치)와 `EnabledPlugins`. 없으면 기존 화면과 같은 구성의 기본값을 쓰고 첫 편집 때 실체화한다. `schemaVersion`은 2를 유지한다. 없는 플러그인의 배치는 지우지 않고 자리표시 타일로 보여 준다.
- **검증**: `Core/WorkspaceLayouts`가 범위·겹침·탭 규칙을 소유한다. UI 미리보기와 저장이 같은 검증을 쓴다. 손상된 항목은 로드 때 버린다.
- **편집**: 평소에는 위젯 조작만 받는다. 편집 모드에서만 격자를 보여 주고 드래그 이동·크기 조절·추가·제거를 받으며, 위젯 내부 입력은 막는다. 드롭 때만 저장하고 실패하면 이전 배치로 돌아간다. Esc는 드래그 취소 → 편집 종료 순이다.
- **탭**: 설정 탭은 복구 경로이므로 항상 마지막에 표시한다. 나머지 내장 탭은 순서 변경·숨김, 사용자 탭은 이름 변경·삭제까지 가능하다. 숨긴 탭도 앱 내부 이동(채팅 토스트 등)으로는 열 수 있다.
- **위젯 수명**: 내장 위젯은 기존 뷰 인스턴스를 단일 배치로 재사용하고 제거해도 폐기하지 않는다. `OverlayDashboardView`는 보이는 구역이 하나라도 있으면 시계·날씨 갱신을 유지한다.

## 플러그인 경계

- 계약은 UI 전용 어셈블리 `Facet.Plugins`뿐이다. Core·Store·AppData를 노출하지 않으므로 계약을 통해서는 사용자 기록을 읽을 수 없다.
- `<data>/plugins/<폴더>/plugin.json`만 읽어 목록을 만들고, 코드는 사용자가 설정에서 켠 뒤에만 실행한다. 켤 때 폴더 안 모든 DLL의 SHA-256을 저장한다. 값이 달라지면 다시 켤 때까지 불러오지 않던 규칙은 [0079](0079-plugin-auto-reload-at-launch.md)이 대체한다.
- 플러그인마다 별도 `AssemblyLoadContext`를 쓴다. 등록·위젯 생성 예외는 해당 플러그인 오류나 자리표시 타일로 격리한다.

## 한계

플러그인은 샌드박스가 아니다. 앱과 같은 프로세스·권한으로 실행되므로 파일과 저장 데이터에 직접 접근할 수 있고, UI 스레드에서 멈추거나 처리되지 않은 예외를 던지면 앱에 영향을 준다. 그래서 명시적 활성화를 요구한다. 끈 플러그인의 어셈블리는 앱을 다시 시작할 때까지 메모리에 남는다. 격리가 필요해지면 별도 프로세스 모델을 새 ADR로 검토한다.

플러그인 작성법은 [plugins/README.md](../plugins/README.md)에 있다.
