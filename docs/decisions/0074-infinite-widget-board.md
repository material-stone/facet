# 화면 3배 위젯 보드와 탭별 시점

2026-11-04: [0073](0073-widget-grid-and-plugins.md)의 12×8 고정 격자를 원점 중심의 넓은 격자로 바꾸고, 설정을 뺀 모든 탭에서 위젯을 편집할 수 있게 한다.

## 결정

- **보드**: 창 전체를 쓰며 탭 메뉴와 편집 버튼은 그 위에 뜬다. 원점에서 각 방향으로 창 크기의 1.5배까지 온전한 칸만 두어 전체가 화면의 3배다. 창 크기로 정해지므로 저장 검증은 하지 않고 편집 UI가 제한한다. 창이 줄어 범위 밖에 놓인 위젯은 지우지 않는다. 화면은 보드 밖으로 나가지 않는다.
- **좌표**: 칸 좌표는 음수를 허용한다. 원점은 네 칸 사이 간격의 정중앙으로, 칸 (x, y)는 원점에서 `x·피치 + 간격/2`에 놓인다. `GridVersion`이 2보다 작은 저장 배치는 로드 때 (-6, -4)만큼 한 번 옮겨 기존 배치가 중앙에 오게 한다.
- **시점**: 탭마다 `View`(원점 이동 벡터 X·Y는 화면 픽셀, `Zoom`은 1/3~3)를 저장한다. 사용자가 시점을 바꾸기 전에는 `View`가 없고, 원점을 중앙에 둔 100%로 표시한다. 작은 창에서 기본 배치가 잘려도 자동으로 축소하지 않는다. 확대·축소는 100%를 건너뛰지 않고 그 값에서 한 번 멈춘다.
- **조작**: 이동·확대는 편집 모드에서만 받는다. 평소에는 위젯과 페이지 입력이 그대로 동작해야 하기 때문이다. 시점은 편집 모드를 나올 때만 저장하고, 실패하면 화면의 시점을 유지한 채 알리고 다음 종료 때 다시 저장한다. 원점 버튼은 배율을 유지하고 이동만 되돌린다.
- **고정 탭**: 일정·수면·채팅의 기존 화면은 위젯으로 옮기지 않고 그 위에 보드를 얹는다. 평소 빈 칸의 입력은 페이지로 통과하고 편집 모드에서는 보드가 받는다. 창 크기에 맞춰 배치되는 페이지를 고정 크기 타일로 옮기면 레이아웃이 달라지기 때문이다. 설정 탭은 복구 경로이므로 보드를 두지 않는다.

## 한계

위젯이 페이지 위에 놓이면 그 아래 페이지 영역을 가린다. 앱이 편집 모드인 채 강제 종료되면 저장하지 않은 시점은 사라진다.
